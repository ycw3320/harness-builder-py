# 아키텍처

## 3계층 단방향 의존 (ADR-0001)

```
harness_app (GUI)        ── 위젯·이벤트. 프레임워크 의존(Flet/Qt). 로직 없음.
   │  (호출)
   ▼
harness_fs (디스크)       ── 가상 파일트리 ↔ 실제 폴더. 직접쓰기·병합·역import. pathlib.
   │  (호출)
   ▼
harness_core (순수 로직)  ── IR·export·lint·simulate·preset. GUI/FS 무의존. PM1 완료·동결.
```

- **단방향:** 위 계층만 아래를 import 한다. `harness_core`는 아무것도 import 하지 않는다.
- **상위 불변식:** 코어는 **무수정·소비만**. 코어를 바꾸면 골든 게이트(ADR-0003)가 즉시 깨지므로, 변경은 의도된 동치성 변경일 때만.
- **프레임워크 격리:** GUI 의존은 `harness_app/`에만. Flet↔Qt 피벗 시 `harness_app/`(+ fs의 파일다이얼로그 호출부)만 교체, 코어·FS 로직 100% 재사용.

## 데이터 흐름 (안내형 누적 흐름, §0.6)

```
프리셋 로드 → state(IR)
   ↑ patch/CRUD                         ┌─ simulate(ir, action) → 결과 칩 (실시간)
사용자 편집 ──→ state 변경 ──(구독)──→ ├─ lint_ir(ir)        → 경고/보안 (실시간)
   ↑ "외부 LLM에 이렇게 요청" 복사       └─ assemble_project(ir) → 파일트리 미리보기
외부 LLM 답 붙여넣기                                      │
                                          write_tree(tree, dest) → 실제 폴더 생성/병합
```

1. 영역(계층)별로 "설정 가능 항목"을 제시한다.
2. 항목/영역별로 "외부 LLM에 이렇게 요청하세요" 프롬프트를 제안·복사한다(앱은 LLM을 직접 호출하지 않음 — 결정론·오프라인 유지).
3. 사용자가 외부 LLM 답을 채우면 = 소규모 컨텍스트가 누적된다.
4. 매 편집마다 시뮬레이터·lint·완성도가 실시간 갱신된다.
5. 6계층이 채워지면 하네스 완성 → 폴더로 내보낸다.

## 계층별 책임
- **harness_core:** "무엇을 산출하는가"의 진실. IR(6 kind) → `VirtualFile[]`. 순수 함수.
- **harness_fs:** "가상 → 실제"의 경계. 안전(비파괴·traversal 차단)이 책임.
- **harness_app:** "사용자와의 대화". 위젯은 state/fs를 호출만(B7 controllers), 로직을 담지 않는다.

## 북극성 적용
초심자가 막히지 않게: 프리셋에서 시작 → 영역별 안내 → 실행 전 시뮬·lint로 안전 확인 → 한 번에 폴더 생성. "전문가만 아는 것"을 전제하지 않는다.
